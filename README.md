# Eho

**Локальный ИИ-агент для поиска и анализа технической документации.**

Eho помогает инженеру разбирать инфраструктурные задачи, искать информацию в базе знаний Obsidian и получать рекомендации с опорой на найденные материалы.

Проект использует локальную LLM через LM Studio и собственную Python API. Основной сценарий работы не требует обращения к внешним ИИ API.

## Возможности

- **RAG по базе знаний Obsidian.** Поиск релевантных технических заметок и инструкций.
- **Анализ инцидентов.** Обработка описаний проблем и подготовка рекомендаций по устранению неисправностей.
- **Ссылки на источники.** Возможность перейти к заметкам, на которых основан ответ.
- **Интеграция с Obsidian.** Запуск API, настройка модели и получение результатов непосредственно из рабочего пространства.
- **Telegram-бот.** Отправка запросов и получение ответов через Telegram.
- **Локальная LLM.** Поддержка OpenAI-compatible API через LM Studio.

## Требования

- Linux или другая совместимая с Python среда.
- Python и `pip`.
- LM Studio с загруженной совместимой языковой моделью.
- Obsidian для работы через плагин.
- Telegram Bot Token для использования Telegram-интеграции.

## Установка

Перейдите в каталог проекта:

```bash
cd ~/SOFT/Projects/Eho
```

Создайте виртуальное окружение и установите зависимости:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Настройка LM Studio

1. Загрузите подходящую модель в LM Studio.
2. Запустите локальный сервер с OpenAI-compatible API.
3. Укажите адрес API и идентификатор модели в настройках плагина Eho.

Пример используемой конфигурации:

```text
Base URL: http://127.0.0.1:1234/v1
Model:    google/gemma-4-e4b
```

Это пример рабочей конфигурации, а не обязательная привязка к конкретной модели. Доступность модели зависит от установленного окружения LM Studio.

## Запуск API

Из корня проекта выполните:

```bash
.venv/bin/python -m uvicorn app.api.main:app \
  --host 127.0.0.1 \
  --port 8765
```

После запуска API доступен по адресу:

```text
http://127.0.0.1:8765
```

Проверка состояния:

```bash
curl -s http://127.0.0.1:8765/api/health
```

Ожидаемый ответ:

```json
{"status":"ok"}
```

Для остановки API используйте `Ctrl+C` в терминале, из которого запущен сервер.

## Интеграция с Obsidian

Плагин Eho служит интерфейсом для работы с API.

Он позволяет запускать API, передавать настройки модели и получать результаты анализа. При запуске через кнопку плагина синхронизируются настройки Telegram и проверяется состояние бота.

Для ручной проверки API используются следующие эндпоинты:

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `GET` | `/api/health` | Проверка доступности API |
| `POST` | `/api/analyze` | Анализ запроса |
| `GET` | `/api/telegram/status` | Проверка состояния Telegram |
| `POST` | `/api/telegram/start` | Запуск Telegram-бота |
| `POST` | `/api/telegram/config` | Передача настроек Telegram-интеграции |

## Интеграция с Telegram

Telegram-бот позволяет взаимодействовать с Eho через сообщения.

Для работы интеграции необходимы:

- Telegram Bot Token.
- Настроенная модель и доступный LM Studio API.
- Запущенный Eho API.
- Синхронизированные настройки Telegram.

Проверить состояние интеграции можно командой:

```bash
curl -s http://127.0.0.1:8765/api/telegram/status
```

Ответ содержит признаки конфигурации бота и модели, а также состояние запуска.

## Диагностика

**API не отвечает**

Проверьте, запущен ли сервер:

```bash
pgrep -af uvicorn
```

Проверьте доступность эндпоинта:

```bash
curl -s http://127.0.0.1:8765/api/health
```

**LM Studio недоступна**

Проверьте локальный сервер LM Studio и правильность Base URL и идентификатора модели.

**Telegram-бот молчит**

Проверьте состояние интеграции:

```bash
curl -s http://127.0.0.1:8765/api/telegram/status
```

Если API работает, но бот отключён, проверьте запуск через плагин Obsidian или эндпоинт `/api/telegram/start`. При сетевых ошибках отдельно проверьте доступность `api.telegram.org`.

## Безопасность

- API по умолчанию привязан к `127.0.0.1` и не предназначен для прямого внешнего доступа.
- Не публикуйте Telegram Bot Token и другие секреты в Git.
- Не коммитьте виртуальное окружение, журналы, локальные данные и конфиденциальную базу знаний.
- Перед размещением API в доступной извне сети настройте аутентификацию и сетевые ограничения.

## Статус проекта

Eho развивается как локальный инструмент для инженерной работы с инфраструктурой и технической базой знаний. Архитектура предусматривает поиск по документации, анализ запросов локальной языковой моделью и доступ к агенту через несколько интерфейсов.
